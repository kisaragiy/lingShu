# ADR-001: 安全护栏双层架构

## 状态
已执行

## 背景
WorkBuddy 的权限双层架构（Default/Full Access + 危险操作确认矩阵）是唯一值得移植进灵枢的核心特性。灵枢在 v0.28 前没有操作级别的安全控制——Agent 一旦获得用户信任，就可以执行任意操作（删文件、发消息、跑脚本），没有二次确认机制。

## 方案对比

| 方案 | 优势 | 劣势 |
|------|------|------|
| **A: 双层模式 + 确认矩阵**（选此方案） | 细粒度控制、用户无安全感时也有兜底 | 实现成本中等、需改造 `call_tool` 入口 |
| **B: 单层权限（管理员/普通用户）** | 实现简单 | 一旦授权=全权，没有操作级别的拦截 |
| **C: 每次操作都弹窗确认** | 最安全 | 用户体验极差、高频操作不可用 |

## 决策
选择方案 A。原因：
1. 灵枢是本地优先的应用，用户可信度高，不需要每一次都确认
2. 但某些操作（批量删文件、执行脚本、对外发送消息）一旦误操作不可逆
3. 双层模式让用户在「信任」和「安全」之间自由切换——日常用 Default 有兜底，批量操作时切 Full 减少打扰

## 后果
- 接受的风险：Full 模式下确认矩阵完全关闭，用户误操作无保护
- 代价：`call_tool` 入口增加了权限检查逻辑，每个工具调用多~2μs 开销
- 需要在 UI 层加模式切换开关和当前模式指示器

## 实现要点
- `mode.py`: Default(需确认)/Full(跳过确认) 两种模式，持久化到文件
- `risk.py`: 危险操作分类（敏感路径/批量删除/脚本执行/外部发送/网络请求）+ 确认码机制
- `backup.py`: 覆盖写前自动存 `.bak` 副本
- `trash.py`: 删除走回收站 `~/.agent-harness/trash/`
