# 灵枢知识管道（LingShu Knowledge Pipeline）

> **一句话**：把"踩过的坑"变成"事前拦截的规则"，并让管道能被人自然语言问、能自动从每日笔记沉淀新坑。
> **定位**：灵枢的 A 路线真实场景（独立资产，不接入 Hermes 工作流）。
> **目录**：本目录 `docs/knowledge-pipeline/`，灵枢自身组成部分。

---

## 一、问题：为什么要做这个管道

灵枢作为"AI 应用开发能力样板"（A 路线），最致命的缺口是**缺"用 AI 解决过真实问题"的证据**——一个自己都不用的项目是样板房，不是正经项目。

这是把灵枢接成"自己的知识/任务管道"时，盘出来的**真实痛点**：

1. **知识高产出、零索引** —— `~/knowledge/daily/` 14 篇流水，13 篇含坑/教训沉淀（知识在大量产生），但 7 个领域目录里 4 个没有 index，6 个散件 md 无归属，检索靠脑子记。
2. **教训从没在事前拦住** —— 所有坑都是**事后**记进 daily 的（"FYTHONPATH 污染""cron 不支持参数""工具是 mock"），没有任何机制在下一次发生之前拦住你。这就是"复现失败"本身。
3. **外部世界对它的磨损缺失** —— 一个没被作者自己使用的项目，缺最难的那一环（真实反馈/迭代/踩坑）。

结论：做一个**防复现知识管道** —— 把 `daily` 里的事后教训，转成**事前拦截规则**，并在动作发生时刻跳出来拦。

---

## 二、架构：四个组件

```
┌────────────────────────────────────────────────────────────┐
│  1. 规则库 (knowledge-rules-*.md)                            │
│     结构: {trigger, lesson, block_hint, source}              │
│     v1 技术复现坑 (R-01~10) · v2 AIGC/GPU/记忆 (R-11~21)     │
│     career 求职线 (R-22~30)                                   │
├────────────────────────────────────────────────────────────┤
│  2. guardian.py — 拦截器 + 检索层                            │
│     guard(action)     动作 → 命中规则(产品暗示/PYTHONPATH…)   │
│     search_rules(q)   自然语言 → 打分排序 → 返回 top+来源      │
│     load_rules()      结构化解析 → {rule_id: 对象}            │
├────────────────────────────────────────────────────────────┤
│  3. extract_candidates.py — 沉淀机制                        │
│     扫 daily → 信号词(坑/教训/根因) → 抽候选规则 → 人工确认    │
├────────────────────────────────────────────────────────────┤
│  4. 测试 (test_guardian.py + test_knowledge_pipeline.py + test_rules_v4.py)     │
│     28 用例 — 拦截/检索中文分词/沉淀/数据完整性/边界          │
└────────────────────────────────────────────────────────────┘
```

## 三、数据模型

每条规则是一个结构化对象（`load_rules` 返回）：

```python
{
  "rule_id": "R-22",
  "title": "简历措辞：产品暗示词（最大雷）",
  "trigger": "即将在简历项目经历里写'平台/产品/系统/PWA/APK/pip install/已上线'",
  "lesson": "'500 投 0 面'最大根源。写'平台'会让面试官按产品标准追问用户量/上线网址，答不上就挂",
  "block_hint": "用'框架/实践/工具链'替代'平台/产品/系统'。定位写'个人技术项目'而非'产品'",
  "source": "resume-builder skill + daily/2026-08-23.md",
  "haystack": "title+trigger+lesson+block_hint 拼接(供检索)"
}
```

**source 单一来源真相**：规则号 → 来源 daily 映射（`RULE_SOURCE_MAP`），不手改每个规则文件。这保证 provenance 可查、不漂移。

## 四、用法

### 拦截器（guard）—— 你告诉我"我要做 X"，它拦住"X 你踩过"
```bash
python guardian.py "给简历写平台和PWA"     # → 命中 R-22/23/24/29
python guardian.py --list                  # 列出全部 30 条规则
```

### 检索层（search_rules）—— 你问"我以前怎么处理 X"，它给规则+来源
```bash
python guardian.py --search "显存不够怎么办"
# → R-11 (score=0.03, daily/2026-08-14.md) GPU/显存竞争
python guardian.py --search "招呼语怎么写"
# → R-25 (score=0.09, boss-job-search skill) 投递:招呼语定制
```

### 沉淀机制（extract_candidates）—— 扫 daily 抽候选规则
```bash
python extract_candidates.py --min-signals 2   # 扫全部 daily，信号词≥2 抽候选
python extract_candidates.py --out candidates.md
```
> **非全自动入库**：候选需人工确认后合并进规则库（防 R-17 自动管道灌垃圾）。

### 测试
```bash
cd docs/knowledge-pipeline
unset PYTHONPATH   # 关键！防 Hermes venv 劫持（见 R-01）
./.venv/Scripts/python.exe -m pytest test_guardian.py test_knowledge_pipeline.py -q
# → 28 passed
```

## 五、设计决策（ADR 摘要）

### ADR-1：为什么中文检索用 2-gram 分词，不是 jieba
- **决策**：零外部依赖，用中文 2-gram 滑动窗口 + 反向匹配（规则关键词 → query）。
- **坑**：`re.findall(r"[\w\u4e00-\u9fff]+", ...)` 会把整段中文当一个 token（"\u4e00-\u9fff" 对 CJK 也匹配，无空格分隔）→ "显存不够怎么办" 整体在规则里不存在 → 命中 0。
- **解法**：不切 query，改成从规则侧的 title/trigger/lesson 提取特征词（中文切 2-gram，英文按词），统计有多少特征词出现在 query 里。中文 2-gram 能捕获"显存/队列/静默"这类词。

### ADR-2：为什么规则库保持 md 文本，不用数据库
- **决策**：规则是**人读为主**的资产（要能 review、能 diff、GitHub 可验证），md 纯文本最合适。数据库反而增加维护成本、且丢失可读性。
- **tradeoff**：检索是简单词匹配，不是向量语义检索。对**防复现**这种"关键词强相关"场景够用；真要语义检索（模糊问法），可后续接浮点嵌入，但当前场景 ROI 为负。

### ADR-3：为什么沉淀机制"人工确认合并"，不全自动
- **决策**：信号词抽出来的候选**不是规则**——它可能是一条正常记录，也可能断章取义。全自动入库会灌垃圾（R-17 的教训：反射器自动提取 fact 364 出错）。
- **分界**：机器负责"发现候选"，人负责"判断并合并"。这符合灵枢的工程哲学——工具系统质量决定 agent 能力边界，但判断力是人的。

### ADR-4：为什么是独立资产，不接 Hermes
- 用户拍板选 C（归档不接线）。保持"灵枢是独立项目、不是 Hermes 补丁包"的边界。
- **诚实标注**：这意味着"主动提醒"目前停留在"工具在那、用不用看人"，不实现真正的主动拦截。这是有意为之——避免让灵枢长进 Hermes 流程，等规则库更成熟再谈主动。

## 六、当前边界（诚实的现状）

| 维度 | 现状 |
|------|------|
| 规则条数 | 30（技术 21 + 求职 9） |
| 检索能力 | 关键词/2-gram 匹配 + 来源标注，**非向量语义** |
| 主动拦截 | ❌ 未接 Hermes 动作入口（C 归档决策） |
| 沉淀 | ✅ 能扫 daily 抽候选，**需人工确认合并** |
| 覆盖领域 | 技术复现 + 求职（用户踩坑最多的两条线） |
| 测试 | 38 用例，覆盖拦截/检索中文/沉淀/边界/v4 加权信号（原 28 + R-31~35 与加权抽取 10） |

**已知缺口**：公开输出/面试答问线尚无规则；检索是关键词不是语义。

## 七、与面试叙事的关系（A 路线）

这套管道本身就是**"用 AI 解决真实问题"的证据**——它不是演示，是解决"知识散/坑不拦"这个真实问题的工具。面试讲它时，重点不是"我写了 30 条规则"，而是：

> "我发现自己的高频坑（PYTHONPATH 污染、cron 参数、招聘错配）都是事后才记录、事前从不拦截。于是我做了一个知识管道：把教训结构化、加检索、加沉淀机制。它验证的是『能用 Agent 解决真实重复劳动』这个能力，而不是『我背了个 RAG 演示』。"
