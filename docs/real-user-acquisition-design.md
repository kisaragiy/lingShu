## 0. 一句话目标

让 **3–5 个非技术熟人**（电商运营 / 学生 / 同事）在**无人陪同**的情况下把灵枢跑起来、完成一次真实任务，并留下**可复述的问题记录**。

> 为什么做这件事：面试必问「你这项目谁在用？」。当前答案是"没人用"，这比"技术不够"更致命。本项目唯一目的是把这个空格填上。

---

## 1. 成功标准（可验证，逐条打勾）

| 级别 | 标准 | 验证方式 |
|---|---|---|
| **P0** | ≥3 个用户**独立**完成「安装 → 首次任务」（我不在场） | 微信记录/截图/日志时间戳 |
| **P0** | 收集到 ≥3 个**真实使用问题**（含场景描述，非"不好用"这种无效反馈） | 结构化记录到 `docs/user-feedback.md` |
| **P1** | ≥1 个用户**主动第二次使用**（留存信号，而非礼貌试用） | 使用日志/主动询问 |
| **P2** | 能回答面试 L1-1：「谁在用、上线后遇到什么问题、怎么修的」 | 口述 3 分钟不卡壳 |

**反面标准（明确不算成功）**：用户装了打不开也算（那是失败但记录有价值）；用户出于人情装一次再也不用（无留存信号）。

## 2. 用户与场景（3 类，按落地难度排序）

| 用户 | 真实场景 | 灵枢对应能力 | 卖点是否成立 |
|---|---|---|---|
| **电商/运营** | 竞品调研、素材/卖点整理 → 出文档 | `apps/research`（SearXNG→DDG 降级 + 5 层解析 + HTML 报告） | 🔶 待验证：是否比手动搜索省时 |
| **学生（考研/论文）** | 资料整理、论文/文献问答 | RAG 知识库（PDF/DOCX/TXT → 向量/BM25） | 🔶 待验证：效果能否打平 ChatGPT |
| **同事** | 报告整理 | 报告生成 `/v1/reports` | ⚠️ **公司数据不接**——只能用公开资料，价值打折 |

**关键质疑（必须回答）**：用户为什么不用 ChatGPT？
- 候选差异点：① 本地知识库 + 本地模型（数据不出本机）② 多 Agent 调研**一次性出结构化报告**（非对话）③ 可定制工具/技能
- 🔶 其中 ① 对本批用户**不成立**（他们没这个顾虑）；真正可能成立的是 ②
- **结论：卖点尚未验证，这是本设计最大的风险，必须先小规模试**

## 3. 约束（用户已拍板）

1. **形态**：先本地 exe 发熟人（0 成本），不上云、不做小程序
2. **用户范围**：电商运营 / 学生 / 同事（3 类）
3. **目标**：3–5 个真实使用者，"能讲出真实问题"即达标
4. **红线**：不接公司内部数据

## 4. 现状盘点（真实，非推测）

### ✅ 已有（实测目录查证）
- **安装包**：`dist/LingShu-Setup-0.75.2.exe`（69.5 MB，Inno Setup，2026-09-07 构建）
- 应用主体：pywebview 桌面窗口 + FastAPI(:8788) + LangGraph Supervisor-Worker
- **多用户**：JWT + RBAC + `owner_id` 会话隔离（**天生支持多人，这是找真实用户的关键基建**）
- RAG 知识库（上传/索引/查询）、报告生成、40+ 工具、三级降级搜索
- 打包脚本：`scripts/lingShu_installer.iss` + `lingShu.spec`
- 另有 Docker / 微信小程序（本次不用）

### ❌ 缺口（需本项目解决）
| # | 缺口 | 影响 |
|---|---|---|
| G1 | **无终端用户引导**：`docs/quickstart.md` 是开发者视角（pip / .env / API key） | 非技术用户拿到 exe 不知道从哪开始 |
| G2 | **API key 方案缺失**：官方文档要求用户自配 OPENAI/DEEPSEEK key | 劝退非技术用户 |
| G3 | 无场景化模板（用户不知道拿它干什么） | 装了不会用 |
| G4 | 无反馈收集通道 | 收不到结构化问题，面试讲不出 |

### ❓ 未验证假设（诚实标注，评审请重点打这里）
- **U1**：exe 在**干净电脑**上能否跑通？本机是开发机（有 venv/.env/依赖），**无法模拟干净环境** → 未验证
- **U2**：pywebview 依赖 **WebView2 Runtime**，目标机器未必预装（Win10 常见缺失）→ 未验证
- **U3**：Qwen3:1.7b 本地兜底模型的实际可用性（AGENTS 记载 v0.63 支持自动检测 Ollama）→ 未测
- **U4**：调研助手产出质量是否真省用户时间 → 未测

## 5. BFS 需求树（枚举所有边界，不遗漏）

### A. 分发
- A1 交付通道：微信传 / 网盘 / U 盘（69.5 MB 微信可直接传）
- A2 **杀毒误报**：PyInstaller 打包 exe 的常见误报 → 用户不敢装
- A3 管理员权限需求（Inno Setup 默认可能需要）
- A4 **WebView2 依赖缺失**（U2）→ 装了打不开
- A5 系统版本兼容（Win10/11、32/64 位）
- A6 磁盘占用（安装后约 200–300 MB）

### B. 配置
- B1 **LLM API key 谁出**（🔴 最关键阻塞）
- B2 无 key 能否可用（本地 ollama 兜底路径，效果如何）
- B3 首次启动流程（创建管理员账号的引导是否清晰）
- B4 端口冲突（8788 被占时的行为）
- B5 搜索链路：SearXNG(:4000) 未部署时是否自动降级 DDG

### C. 使用
- C1 用户是否知道拿它干什么（**场景模板缺口 G3**）
- C2 首次任务成功率（第一次用就失败 = 流失）
- C3 中文引导/帮助完整性
- C4 结果质量是否达到"愿意再用"（vs ChatGPT）

### D. 数据与隐私
- D1 用户上传资料存哪（本机 SQLite/NPY？）
- D2 **数据是否出本机**（用云端 API 时必然出）→ 必须明示
- D3 用户能否删除自己的数据
- D4 多用户之间的隔离强度（owner_id 是否够）

### E. 反馈收集
- E1 通道：内置反馈按钮 / 微信回访 / 日志分析
- E2 区分「产品缺陷」vs「用户不会用」
- E3 结构化记录（成为面试素材）

### F. 失败路径（必须提前堵）
- **F1 用户装了不用**（最可能发生）
- F2 用户电脑跑不动 / 依赖缺失
- F3 首次遇 bug 即放弃（无恢复路径）
- F4 中途因成本/隐私顾虑退出
- F5 用户礼貌性反馈（假信号，无法用于面试）

## 6. 风险与对策（P0/P1/P2）

| 级别 | 风险 | 对策 | 验收 |
|---|---|---|---|
| **P0** | **B1 key 阻塞** | 方案 a：内置体验 key + 限额（成本可控但需防滥用）<br>方案 b：引导用本地 ollama（0 成本，质量降）<br>方案 c：给每个用户单独发 key（管理成本） | 用户 10 分钟内完成首次任务 |
| **P0** | **A4/A2 装不上** | 安装包内附 WebView2 引导 + 已知误报白名单说明；**先找 1 人试装** | 至少 1 台干净机装成功 |
| **P0** | **F1 装了不用** | 给 3 个场景模板（一键任务）+ 首次使用必须产出一次真实结果 | ≥3 人完成首次任务 |
| **P0** | **C1 不会用** | 一页《非技术用户指引》（截图 + 3 个场景） | 用户无需问我即会用 |
| **P1** | F3 遇 bug 放弃 | 内置"导出日志"按钮，用户可一键发我 | 收集到带日志的问题 |
| **P1** | D2 隐私顾虑 | 首次启动明示"数据去向"，给本地模型选项 | 无人因隐私拒绝 |
| **P2** | A6 磁盘 / A3 权限 / B4 端口 | 文档说明 + 错误提示优化 | 不再是阻塞 |
| **P2** | E2/E3 反馈质量 | 设计 3 问回访模板 | ≥3 条可讲的问题 |

## 7. 最小可行方案（MVP，两周）

**第 1 周：把"能给别人用"补齐**
1. 写《非技术用户上手指引》（1 页，截图 + 3 场景）→ 补 G1
2. 定 key 方案（**倾向：内置限额体验 key + 明示数据去向**）→ 补 G2
3. 加 3 个场景模板（竞品调研 / 资料问答 / 报告整理）→ 补 G3
4. 找 **1 个熟人试装**，记录全部卡点 → 验 U1/U2

**第 2 周：扩到 3–5 人 + 收反馈**
5. 建 `docs/user-feedback.md` 结构化记录 → 补 G4
6. 每人一次 15 分钟回访（3 问：用来干什么 / 卡在哪 / 会不会再用）
7. 把真实问题修掉 1–2 个 → 形成"上线→发现问题→修复"闭环（面试素材）

---

## 8. 不做什么（明确边界）

- ❌ 不上云、不做域名备案、不做小程序审核（用户已拍板 0 成本）
- ❌ 不为拉用户改架构（灵枢是面试作品，不是创业项目）
- ❌ 不接公司内部数据（红线）
- ❌ 不追求用户数（3–5 个即可，重点是有真实问题）
- ❌ 不为凑用户做推广/发帖（外部操作需审批，且 ROI 低）
