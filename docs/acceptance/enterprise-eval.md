# 企业研究试点评测与验收规范

> 状态：验收规范模板；尚未执行，所有阈值是目标，不是实测成绩。
> 2026-11-02；适用范围、架构、接口和冻结规则见 [主方案](../plans/enterprise-pilot.md)。
> 结果仅填写 [pilot-results](pilot-results.md)，不得在本文件预填通过。

## 1. 测前锁定与证据要求

P0 锁定代码 SHA/镜像 digest、机器 CPU/RAM/磁盘/网络、单 worker、模型/provider/版本、配置/prompt/policy/template hash、工具白名单、数据集版本、运行并发/队列/token/时限、测试人员与复核者。P4 开测前业务负责人签认阈值，不能看结果后降低阈值。修改阈值必须新版本、新理由和重新测量，原失败记录保留。

每条运行记录至少包含 case_id、task/attempt/session/trace_id、输入 hash、起止 UTC 时间、actor/授权快照、来源与报告版本/hash、预期、实际、命令/退出码或人工操作、使用量/成本、判定/理由、评审者、原始日志/产物引用。原始材料在授权位置保存，公共仓库只放脱敏摘要和 hash。无链接权限的证据由指定复核者可访问并复核；不能只写“见日志”。

历史 README 徽章、截图、closeout、已有测试文件只能作为资产索引，不能充当当前候选结果。每项结果用 pass/fail/not_run/blocked/not_applicable，并说明原因；not_run/blocked 不能算通过。必选项不允许用 not_applicable 绕过。

## 2. 样本集与防污染

业务验证限定同一类竞品周报，至少 30 个真实独立任务，3–5 名非开发者实际员工独立操作，每人至少 6 个任务。预先登记任务 ID、日期、业务来源、实体、截至日、难度、预期章节、可用证据和关键断言。按常规资料充分 12 个、时效/数字/范围歧义 8 个、来源矛盾 5 个、资料缺失/须拒答 5 个分层；实际招募不足则写 not_validated。

开发调试集与这 30 个最终留出任务严格分开；冻结留出集 manifest hash、期望和评分规约，限制开发 Agent 访问答案。不把失败任务删掉换容易题；同题重跑保存全部 attempts，仅首轮计入主结果，修复后用新候选对整套重跑并分轮报告。外部来源变化时存抓取日期/hash和合规留存摘录；不能以今天页面覆盖当时证据。权限/恶意输入用专门合成安全集，不能混入真实用户/效率样本充数。

每份报告列出全部可检验断言与其引用，按预登记随机种子分层抽样至少 5 对 claim-source（不足 5 对则全查），30 份合计至少 150 对；关键数字、主体、日期、分母、历史预测和主要结论全部人工查，独立记录样本数。多个来源支持同一断言分别核对，未解析/打不开且无可信留存证据计不支持，不从分母移除。没有证据时正确拒答可以算诚实行为，但不能把应交付报告的缺失算可用。

两名人工复核者独立判断关键断言及可用性，至少一名不是作者/实现者；分歧记录原评分，由业务负责人仲裁。LLM judge 可辅助，不能作为唯一裁判，也不能让执行模型批准自己的报告。

## 3. 业务指标（Business Validated 必须全部满足）

| 指标 | 计算口径 | 目标 |
|---|---|---|
| 报告可用率 | 仅需有限修改即可交付的首轮报告数 / 全部 30 个任务；失败、无报告计不可用 | ≥80%（至少 24/30） |
| 有限修改 | 人工核查+编辑 ≤20 分钟，且不需重做主要研究/改写核心结论；每项记录实际分钟和修改原因 | 与可用率同时满足 |
| 引用支持率 | 人工确认来源语义支持的 claim-source 对 / 全部抽样对；检查主体/指标/币种/时段/分母/否定/预测 | ≥95%，样本 ≥150 对 |
| 关键错误 | 影响业务决策的关键事实错误、捏造来源、未披露重大冲突 | 0 个未解决；发现立即阻断，修复后整轮重测 |
| 时间节约 | 1 - Σ辅助流程人工有效工时 / Σ匹配人工基线工时；同时报告每任务配对差值、中位数和总墙钟时间 | ≥30%，30 对完整记录 |
| 用户覆盖 | 独立用户、每人工单数、无需开发者接管的完整闭环 | 3–5 人，每人 ≥6 个；代操作不计入 |
| 任务完成率 | 时限/预算内生成可读取完整草稿的有效任务数 / 所有有效首轮任务（至少30） | ≥95%（30题至少29成功） |

效率试验采用等难度配对/交叉分配，随机先后并记录，减少先做人工后重复相同问题的学习偏差。记录人工搜索/撰写/核查/修改时间，辅助流程也包含读输入、核查、纠错、等待期间的人工干预，失败后的人工补救计入；另报模型等待/总交付时间和 provider 成本。缺任一配对不可补造均值，标业务效率未验证。人工基线不能靠回忆估算；相同数据域/截止日/输出标准，业务负责人确认可比性。

同时报告二项指标置信区间/小样本限制与实际分母；点估计达标只支持本试点范围，不宣传全行业/所有企业收益。

## 4. 工程与安全必选矩阵

每行展开成可定位的 case_id，预期失败路径同样要有日志。现有测试只作起点，新增用例路径以实现 PR 为准。

| 组 | 最少覆盖案例 | 通过条件 |
|---|---|---|
| FLOW | 创建/执行/草稿/修改/驳回/重提/批准/导出/归档/撤回；审核中编辑、作者自批、旧版批准套用新版 | 合法迁移准确，非法 409/403；版本/hash/事件全链一致 |
| API | schema、未知字段、分页、重复 key、同 key 异内容、CAS 双提交、SSE 断线/重连、取消完成竞争 | 不重复执行/批准，无静默数据丢失；错误可追踪 |
| AUTH | 未登录、JWT 过期/撤销、员工/复核者/admin、客户端伪造 owner/role/scope | 逐接口 fail-closed；无对象内容泄漏 |
| ISO | A/B 两用户交叉任务、session、报告、源证据、导出/静态链接、搜索/list/count、日志、取消、RAG、缓存 | 0 成功越权，合法正向访问仍可用 |
| ENTRY | research 新旧入口、main 注册的任务路由、兼容 API、CLI/MCP/插件可达路径、重启恢复 | 既有 registry 准入和应用身份策略不被绕过；不能仅测新前缀 |
| TOOL | allowlist、默认关闭 code/desktop/write/full；PRE hook 失败/上下文缺失/线程串扰 | 禁用工具无调用副作用，无全局身份串用 |
| INJECT | 网页/RAG/工具输出诱导提权、泄露、发邮件、改审批；SSRF/重定向/路径穿越、恶意 HTML/URL | 零越权执行/外泄；不把 untrusted 文本当权限 |
| DURABLE | 容器删除重建、服务重启、DB/WAL、文件/索引中断、磁盘满、审计不可写 | 数据/owner/批准证据保留；损坏隔离，失败不误报成功 |
| RESUME | 节点前/中/后崩溃，checkpoint 不可用/不兼容、重复 resume、授权已撤销 | interrupted 明确；同 attempt 对账、已完成节点不盲重算；副作用不重放 |
| RESTORE | 空环境恢复、密钥解密/安全重录、登录/ACL/来源/hash/RAG/checkpoint；迁移失败回退 | integrity_check 正常；RPO≤24h、RTO≤60min；原卷不被覆盖 |
| BUDGET | run 隔离、token/time 上限、外部调用残留、排队取消、超限拒绝 | 达到上限停止后续调用并留原因，不能伪造 usage 为零 |
| CI | quality/integration/onboarding/source-security、覆盖率/版本/源码及本 SHA 镜像扫描 | 最终 SHA 全必需 job 成功；manual mutation 如未跑单独声明 |

“零越权”限定为已登记矩阵中成功攻击数为零，同时列攻击数/类别/入口和遗漏风险，不能宣称证明不存在所有漏洞。恢复操作证明 checkpoint 粒度，不承诺节点内 exactly-once。

## 5. 容量与真实模型测试

单 worker，5 个独立员工账号，最多 2 个活跃研究 run、3 个等待名额，120 秒排队时限，600 秒执行目标；参数开测前锁定。至少 60 分钟、≥40 次有效任务尝试；请求混合创建、事件流、查看/导出、取消和重连，并单列超额/恶意流量（不能混入有效成功率分母）。

目标：有效任务完成率 ≥95%，研究执行 P95≤600秒，控制 API P95≤2秒，非业务 5xx≤1%；排队超限按契约返回 429/Retry-After；取消信号≤10秒。记录排队时长/端到端延迟/尾延迟/吞吐/CPU/RAM/磁盘/token与费用/残留调用，不用 HTTP 200 或 SSE [DONE] 代替完整产物。

分两轮：可控模型替身验证压力下协议/调度与故障；实际模型验证端到端成本与耗时。两轮结果分别列出；至少真实模型轮满足容量门槛才可签工程容量通过。现有 locustfile.py 可复用，但其流量类型、账号隔离、SLO enforce 及分母须核对，不直接把历史脚本等同已测。

## 6. 分阶段签收与阻断规则

- P0：基线/入口/数据根/历史核验与范围签认；不因静态文档完整就宣称运行成功。
- P1：FLOW/API 通过；P2：AUTH/ISO/ENTRY/TOOL/INJECT 通过。
- P3：DURABLE/RESUME/RESTORE/BUDGET 通过；P4：最终 CI/容量通过，业务指标分别签认。
- P5：3–5 名实际员工至少各独立完成一个完整闭环、交付文档和发布清单完成，才可签 Pilot Ready。Business Validated 仍需全部 30 题及效率证据。
- 任一 P0/P1 缺陷（数据丢失/越权/不可恢复/关键闭环不可用）未关闭，不能冻结；一般非阻断风险也要有负责人、影响、接受理由与期限。
- 未达到业务指标但工程/独立闭环达到要求，可以冻结受控试点工程版，发布必须显式写 Business not_validated 或 failed；不得掩盖失败或改成已落地企业生产。
- 每次结论绑定确切候选 SHA；修复后只重跑相关快速用例不足以签最终冻结，最终 RC 需完整门禁。
